# Daily logger run: prompt template

Replace `HHMM` with `1000`, `1015`, `1030`, `1530` or `1540` (recurring weekday tasks), or `1230` / `1240` (one-time tasks on 1 PM early-close days). `DAY` is worked out by the run itself.

---

Work in the folder ~/SPY-Credit-Spread-Bot (cd there first). Read that project's CLAUDE.md and CLAUDE.local.md hard rules and follow them: this is READ-ONLY. Never call any order or order-preview tool on any server. Do not open any other trading folder. Do not edit code, settings or git.

Task: do exactly one logger run by following collector/logger-task.md, with DAY = today's date in US Eastern time (YYYY-MM-DD) and HHMM = HHMM. First check today's plan with `.venv/bin/python -c "from datetime import date; from spybot import calendar as c; print(c.log_runs(date.fromisoformat('DAY')))"`. If HHMM is not in the printed list (market holiday, no same-day SPY expiry, or a 3:30/3:40 run on an early-close day), write data/raw/DAY/HHMM.skipped.txt with one line saying why and stop. If data/raw/DAY/instruments.json does not exist and HHMM is not 1000, another run may be building it: wait 60 seconds and check again, up to 3 times, before doing step 1 yourself. The run starts about 10 minutes early on purpose (the app may delay recurring tasks by a few minutes). Start the step 2 tool calls 2 minutes before HHMM ET, never earlier than 4 minutes before it; if you are early, wait with a short sleep in Bash. If it is already more than 4 minutes past HHMM, still do the run; the check will mark it late, which is the honest record. Keep it short: as few turns as possible, no planning, no re-reading files, never retype a large tool answer that was saved to a file.

After step 5, write data/raw/DAY/HHMM.notes.txt with: run_et, number of contracts quoted, whether the get_option_quotes answer was saved to a file automatically (yes/no), whether you had to split the call, and the one-line assemble result. Then, whether the run worked or stopped early (but not when it was skipped), run `.venv/bin/python -m spybot health --new-run-problems`. If it prints anything other than `none`, send one push notification (PushNotification tool) starting "SPY bot:" followed by the printed lines (under 200 characters). Only write files inside data/raw/DAY/. Finish with a 3-line summary.
